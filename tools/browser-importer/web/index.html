Recovery · bounded local lifecycle

The authenticated local Recover action above supports the current backend's known Linux-owned child or the package supervisor's verified PID1 management-only startup boundary after a container stop/crash/restart. It retains original lifecycle intent, result and cessation evidence beneath control/local-recovery. It does not run a shell repair script, edit ship data or require a separate recovery app.

Unknown or adopted writers, surviving descendants, a backend reopened in the same namespace without startup authority, and interrupted recovery remain fenced. A missing PID, old journal or checkbox is not proof of cessation. Restart the whole package into management mode first if startup authority is missing; do not clear journals. The native-only maintenance page retains its separate authority and does not gain this local action.

Recovery leaves the ship stopped; Start remains a separate action. If the backend or entire container is down, this page cannot act: use the owner's native Dappnode restart/inspection tools separately. No Docker socket, host privileges or Dappmanager modification is required for supported local recovery.

Attended recovery fallback

Manual: use the owner's authenticated native management tools to inspect the exact package, container, retained volume and updater state. Establish actual Stop completion and an exited observation before repair. If ownership or cessation is uncertain, keep the fence and preserve evidence.

MCP + agent-assisted: an owner-authorized agent may guide inspection and supported native operations through an authenticated MCP connection. Review the exact target and authorize a bounded recovery operation; changed scope requires fresh approval. This page neither connects an agent nor grants native authority; do not paste credentials or ship keys into a chat.

Both paths must retain real command/receipt evidence and generation + sequence bindings. A checkbox, timeout, management response or canned command is not cessation proof. Reconcile pending or interrupted work before retrying; never fabricate a stopped state or clear journals to make Start available.

After verified repair, Start is a separate explicit owner decision with every other instance stopped. Observe the ship process and separately measure ship HTTP readiness. Stock Dappmanager does not need customization for this guidance.
