**Not implementable from this package source on inspected Dappmanager v0.2.129.** The `My custom packages` row uses `prettyDnpName(dnp.dnpName)` in [`PackagesList.tsx`](https://github.com/dappnode/DNP_DAPPMANAGER/blob/v0.2.129/packages/admin-ui/src/pages/packages/components/PackagesList.tsx). The installed package detail heading uses the same formatter in [`ById.tsx`](https://github.com/dappnode/DNP_DAPPMANAGER/blob/v0.2.129/packages/admin-ui/src/pages/packages/pages/ById.tsx). [`format.ts`](https://github.com/dappnode/DNP_DAPPMANAGER/blob/v0.2.129/packages/admin-ui/src/utils/format.ts) takes only the first DNS label, substitutes separators with spaces and capitalizes; `uvm.public.dappnode.eth` becomes `Uvm`. Neither surface reads `shortDescription` or `description`. The [manifest type](https://github.com/dappnode/DNP_DAPPMANAGER/blob/v0.2.129/packages/types/src/manifest.ts) treats `name` as the package identity and provides descriptive metadata but no independent installed-list/display-name property wired to these surfaces.

The existing `shortDescription` is `UVM — Urbit Vere Manager` and the in-app heading/tab title were handled separately in #4. Neither changes the appliance card/detail name. The manifest now also supplies `gettingStarted`: Dappmanager's Info tab renders that Markdown as a dismissible **Getting started** section (or a **show** control after dismissal), explaining what UVM manages and linking to the operator guide. Source and schema checks do not prove it appears in the installed appliance; that needs a separately approved package update and UI readback.

Do **not** rename `uvm.public.dappnode.eth` to influence the formatter: this could create a separate installation and migration requirement. Existing package identity, volumes, services, hostnames and update path remain untouched. A follow-up scoped Dappmanager change could accept a safe, optional display label from trusted installed manifest metadata (with an identity-derived fallback) in both `PackagesList` and `ById`, with UI tests. That would require separate upstream/core authorization and an appliance UI readback; no core change or deployment occurs here.
