# Workflow audit (issue #8)

This is a source-and-published-guidance audit, not a fresh target acceptance. The reference private installation's owner-confirmed login/EAuth and local qualification described in the linked guides are **historical, scoped evidence**. No target, private receipt, credential, pier, image, DNS or certificate was touched for this audit. Start with the [operator guide](operator-guide.md); use the [certificate runbook](owner-certificate-runbook.md) and [maintenance/release runbook](workflow-runbooks.md) at decision points. Companion tunnel settings are authoritative in its [own README](https://github.com/OwlWilderness/dappnode-urbit-ship-tunnel#readme); do not copy tokens or private deployment records into either repository.

## Prioritized automation assessment

| Priority / candidate | Benefit · risk · effort | Boundary and next step |
| --- | --- | --- |
| P1: **public-only certificate preflight/status** (root DER pin, SAN/EKU/chain/expiry, CSR public-key match, actionable refused-state labels) | High · low if read-only · small/medium | Validate public inputs locally without keys or automatic upload; show expiry **before** it becomes an outage. Draft [follow-up A](follow-up-proposals.md#a-public-certificate-preflight-and-expiry-visibility). Does not implement renewal. |
| P1: **private route/configuration preflight** (canonical origin, exact Host/SNI/CA, explicit admin exclusion, effective catch-all) | High · medium · medium | Read-only preview plus owner review; no DNS/route writes or token inspection. Draft [follow-up B](follow-up-proposals.md#b-route-and-package-preflight). |
| P2: **guided certificate exchange UI** (public CSR download, cert upload with validation errors) | Medium · medium · medium/high | Only public files; owner signs and trusts privately. Depends on qualified recovery/renewal semantics; not a silent rotation. Draft [follow-up A](follow-up-proposals.md#a-public-certificate-preflight-and-expiry-visibility). |
| P2: **bundle identity and readiness display** (descriptor/image binding, target mount, STOPPED vs RUNNING vs login-ready) | High · medium · medium | Preflight only; no auto-update, ship Start or Dappstore publication. Draft [follow-up B](follow-up-proposals.md#b-route-and-package-preflight). Coordinate UI wording with [#6](https://github.com/OwlWilderness/dappnode-urbit/issues/6) and tunnel [#1](https://github.com/OwlWilderness/dappnode-urbit-ship-tunnel/issues/1). |
| P2: **nonsecret MCP access preflight/checklist**, not credential automation | Medium · low/medium · small | Check intended Hermes profile, server enabled/selected tool names, and owner-attested Dappmanager mutation gate separately; never print server URL/headers, read key material or invoke upload/install to test permission. Existing CLI list/discovery suffices for a manual preflight; add code only if a repeated sanitized-status gap is demonstrated. No new test matrix for a docs-only gate. |
| Keep manual: CA private-key custody/signing/trust, one-time authority/password, pier backup/restore, single-instance Start, target bundle approval, token/DNS/public-route publication, ship login/EAuth. | High consequence · automation not justified here | Require explicit owner authorization and readback; no agent extraction or silent side effects. |
| Keep manual: Dappmanager MCP key generation/rotation and target **Allow mutating MCP tools** enable/disable. | High consequence · automation not justified here | Owner uses trusted private Dappmanager UI; client-side Hermes MCP server/individual-tool toggles are independent and cannot enforce target-side authorization. |

No new GitHub issues were created; the two scoped drafts are local proposals, not approved implementation. Source relocation [#5](https://github.com/OwlWilderness/dappnode-urbit/issues/5), backup [#7](https://github.com/OwlWilderness/dappnode-urbit/issues/7) and Vere embedded OpenSSL [#3](https://github.com/OwlWilderness/dappnode-urbit/issues/3) remain separate.
